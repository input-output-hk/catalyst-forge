AuthKit integration plan (first draft)

Component A: Package responsibilities and boundaries
- Summary: Keep all auth flows, token logic, and persistence in `lib/foundry/authkit`; keep API server handlers thin. Replace legacy auth in API with AuthKit.
- Deliverables:
  - Implement `authkit.Manager` (construct services, middlewares, route registration, JWKS exposure).
  - Implement minimal HTTP handlers inside `authkit/handlers` for flows defined in `.ai/api/AuthSpec.md` (begin/complete style + cookies/CSRF).
  - Use GORM stores in `authkit/store/gormstore` for persistence; expose `AutoMigrate`.

Component B: Data model & migrations
- Tasks:
  - Call `gormstore.AutoMigrate(db)` at API startup to create tables: `auth_users`, `auth_credentials`, `auth_invites`, `auth_recovery_codes`, `auth_refresh_tokens`, `auth_audit_events`.
  - Confirm indices/uniques align with spec (e.g., refresh token hash unique, email unique).

Component C: Key management & JWT
- Tasks:
  - Initialize `crypto.NewES256KeyManager()`; load ES256 private key (PEM) from config; set current KID.
  - Construct `service.NewTokenService(keys, rand, issuer, accessTTL)` for access JWTs.
  - Expose JWKS via `Manager.RegisterJWKS(r.Group("/"))` at `/.well-known/jwks.json`.
  - Config: `JWT_SIGNING_KEY` (PEM), `JWT_KID`, issuer/audience = public origin host.

Component D: WebAuthn configuration
- Tasks:
  - Configure `service.NewWebAuthnService` with RP name/ID/origin(s), challenge store, credential store.
  - Enforce UV required; admin AAGUID allowlist for hardware-key enforcement.
  - Config: `WEBAUTHN_RP_NAME`, `WEBAUTHN_RP_ID`, `WEBAUTHN_ORIGIN`, `WEBAUTHN_CHALLENGE_TTL`.

Component E: Refresh rotation & cookies
- Tasks:
  - Construct `service.NewRefreshService` with refresh store, user store, token service, rand, TTL, audit store.
  - Use `httpkit.SetRefreshCookie` to set `__Host-refresh_token`; `httpkit.ClearRefreshCookie` on logout.
  - CSRF: Use `httpkit.NewDefaultCSRF` and require `X-Requested-With: XMLHttpRequest` on `POST /auth/refresh`.
  - Config: `REFRESH_TOKEN_TTL`.

Component F: CSRF & CORS
- Tasks:
  - Keep global CORS minimal; for `/auth/*`, rely on strict cookies and CSRF header.
  - For refresh, enforce `SameSite=Strict` and CSRF header via `httpkit.DefaultCSRF`.

Component G: Rate limiting
- Tasks:
  - Provide `rate.Limiter` to `Deps` (memory or Redis). If enabled, wrap sensitive endpoints per spec table.
  - Config toggle: `RateEnabled` + burst/window if applicable.

Component H: Session & policy middleware
- Tasks:
  - Use `Manager.Authenticate()` as global optional auth middleware (injects `AuthContext`).
  - Build `PolicyRegistry` and apply `Manager.EnforcePolicies(registry)` globally.
  - Optionally add `middleware.SessionValidator` for critical subtrees (fresh user/session checks, token revocation via KV).

Component I: Route registration (inside AuthKit)
- Endpoints to implement and register under `/auth`:
  - Login: `POST /login/begin`, `POST /login/complete`.
  - Onboarding: `POST /onboard/begin`, `POST /onboard/complete`.
  - Credentials: `POST /credentials/add/begin`, `POST /credentials/add/complete`.
  - Refresh: `POST /refresh` (header CSRF; returns access token; rotates cookie).
  - Logout: `POST /logout` (revoke family + clear cookie).
  - Logout all: `POST /logout-all` (bump session_version).
  - Recovery: `POST /recovery/init`, `POST /recovery/verify`, `POST /recovery/register/begin`, `POST /recovery/register/complete`.
  - Step-Up: `POST /step-up/begin`, `POST /step-up/complete`.
- Outside `/auth`:
  - `GET /.well-known/jwks.json` via `RegisterJWKS`.

Component J: API server wiring (cmd/api)
- Steps:
  1) Add config/flags/env for WebAuthn, JWT, TTLs, AAGUID allowlist (map to `authkit.Config`).
  2) At startup:
     - Open DB; run legacy migrations; run `gormstore.AutoMigrate(db)`.
     - Build stores: users, credentials, invites, recovery codes, refresh, audit, challenges.
     - Build deps: key manager, rand, clock, limiter, csrf, logger adapter, mailer adapter, KV (Redis recommended).
     - Build cfg: copy durations and booleans from existing cfg to `authkit.Config`.
     - `authMgr := authkit.New(cfg, deps)`.
  3) Router:
     - `r := gin.New()`; `r.Use(authMgr.Authenticate())`.
     - Build and attach `PolicyRegistry` via `r.Use(authMgr.EnforcePolicies(reg))`.
     - `authGrp := r.Group("/auth"); authMgr.RegisterRoutes(authGrp)`.
     - `authMgr.RegisterJWKS(r.Group("/"))`.
  4) Remove legacy auth routes/middleware; keep app routes.

Component K: Policy registry defaults
- Examples to seed (customize later):
  - `RequireAuth("*", "/release/*", "/auth/users", "/auth/users/*", "/auth/roles/*", "/auth/github/*")`.
  - `RequireStepUp("POST", "/release/:id/deploy")` (or exact paths used).
  - `RequireRoles(["admin"], "*", "/admin/*")`.

Component L: Testing
- Tasks:
  - Unit tests in `lib/foundry/authkit` for handlers and services (login, refresh rotation/replay, logout, step-up, recovery, JWKS).
  - API server integration tests for critical flows (happy path + error cases per spec), asserting cookies, headers, and JSON shapes.

Component M: Rollout sequence
- Steps:
  1) Implement `Manager` + core handlers inside `authkit`; pass unit tests.
  2) Add server config/flags; implement adapters (logger/mailer/KV).
  3) Wire in API server; migrate DB; mount routes/middleware; define initial policies.
  4) Replace legacy auth wiring; update docs; run e2e tests.
  5) Enable rate limiting in production; monitor audit events and login/refresh metrics.

Config mapping (quick reference)
- WebAuthn: WEBAUTHN_RP_NAME, WEBAUTHN_RP_ID, WEBAUTHN_ORIGIN, WEBAUTHN_CHALLENGE_TTL
- JWT: JWT_SIGNING_KEY (PEM), JWT_KID, ACCESS_TOKEN_TTL, issuer/audience (public base URL)
- Refresh: REFRESH_TOKEN_TTL; cookie `__Host-refresh_token` enforced by httpkit
- Admin AAGUID allowlist: ALLOWED_ADMIN_AAGUIDS (comma-separated UUIDs)
- Invites: INVITE_DEFAULT_TTL, INVITE_MAX_ATTEMPTS
- Step-up: STEP_UP_WINDOW
- Rate limiting: RATE_ENABLED (+ storage backend)

Open items (to refine during implementation)
- Decide KV backend (Redis preferred) and add minimal adapter.
- Define precise policy patterns for each app route.
- Mailer adapter mapping (recovery/invite/security-alert emails) as needed by flows.
